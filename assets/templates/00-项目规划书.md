# 00 项目规划书（拼积木施工说明书）

<!-- 【产出岗位】产品部·产品经理：G1 过门后动笔，PMO 评审，翻译成大白话让用户确认后才开工。
     这份说明书把第一版拆成一格格积木块，标清每块装什么、谁装、装完用户看什么；
     设计/技术/开发/测试/安全各岗都按它依次推进，像拼乐高一样一块一块来。
     G2 门机器校验：本文档存在 + 「积木块分解」章节 + 覆盖 PRD 全部"必须有" AC + 不私加 PRD 之外的 AC。
     中型以上项目必填；small 项目不需要。
     积木块切分心法：一块 = 用户能看懂、能查验的一个完整体验（不是技术层）；
     第 1 块 = 最小可用骨架（核心动作跑通）；每块含 1~5 条 AC，太大就再拆。 -->

（状态由 PMO 手工维护：待开发 / 已查验 / 免验（须在 05-发布记录 留用户原话）；
  机器的查验进度以状态文件为准，status 命令可查。）

按类型的切分建议：
- data 数据脚本：读入 → 清洗/转换 → 汇总输出 → 异常兜底，一环一块
- admin 管理后台：登录骨架 → 主实体增删改查 → 第二实体/权限 → 备份与账号管理
- front 商用前台：首页（含核心动作） → 内容页 → 详情/联系 → 404 与收尾打磨
- tool 单机工具：通常 1~2 块（小项目根本不需要本规划书）
最后一块固定是「体验打磨」（2~5 条 AC，中型以上必排）：全流程连起来走一遍——功能之间的衔接
（做完这步能不能到下一步）、微文案、完成反馈、空错载三态、可撤销——单块都合格但拼起来别扭，
问题在这一块集中修掉。 -->

## 查验安排

<!-- 每块完成后的查验怎么走：
     ① PMO 亲自走查该块（网页真点 / 脚本真跑 / 后台逐角色登录）；
     ② 演示给用户：让用户亲手点，看顺不顺手；
     ③ 用户点头 → checkpoint 留痕；用户摇头 → 按用户想法做阶段性调整后重验。
