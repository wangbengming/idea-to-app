# idea-to-app · 从想法到应用

> 面向零编程经验用户的工程化 Agent Skill：把一句模糊的想法，一步步变成**双击就能用**的应用。
>
> An engineering-grade agent skill that turns a vague idea from a non-programmer into a working, double-click-to-use application — through a simulated big-tech dev team with machine-enforced quality gates.

## 它解决什么问题

零编程经验的人想做自己要用的软件，通常卡在三件事上：

| 痛点 | idea-to-app 的应对 |
|---|---|
| 听不懂术语，答不了技术问题，容易被吓退 | **说人话承诺**：用户边界零术语；技术决策由班组替用户拿主意，只问"你会怎么用" |
| 说不清需求——只有痛点，没有方案，看到东西才知道要不要 | **探索模式**：痛点翻译成 2~3 个解决方向故事 → 选方向 → 做带水印的样品让用户挑 → 替用户拿主意但随时可改 |
| 一次性生成的应用质量不可控、没法验证 | **工程化流水线**：状态机 + 四道机器评审门 + AC 追溯校验，未经门禁不许交付 |
| 只会做单机小玩具，稍微正经点的需求（批量处理、多人管理、像样的网站）就露怯 | **四类项目画像**：单机工具 / 数据脚本 / 管理后台 / 商用前台，同一套流水线自动换挡——模板、派工、门禁、检查全按类型分派 |
| 一次性交付才见用户，方向跑偏了才知道 | **积木式推进**：产品经理把第一版拆成积木块（00-项目规划书），拼好一块给用户查验一块，不通过就按用户想法做阶段性重构；G4 强制全部块经用户查验 |
| 交付完就散伙，用户不会上线、安全没人管 | **竣工后服务**：阶段 5 给部署建议（定时运行/局域网/静态托管），采纳后出分步方案带教；安全与隐私工程师专职把关（数据分级/攻击面/隐私底线），严重问题一票缓发 |
| Agent 能力没有边界，什么需求都敢接 | **服务边界最高优先级**：只做合法正当用途，违法/侵权/越权需求当场婉拒并给合法替代方向，红线同时注入所有子代理的派工单 |

## 核心特性

- **四类项目画像**——阶段 0 自动归类：tool 单机工具（单文件网页）、data 数据脚本（Python + 双击启动）、admin 管理后台（本地服务 + SQLite）、front 商用前台（多页商用级）。类型决定模板集、派工增量、门禁章节与 verify 检查分支；归类拿不准默认 tool
- **积木式规划与查验**——G1 过门后产品经理产出《00-项目规划书》：把第一版拆成积木块 M1/M2/…（每块含 AC/依赖/用户查验方式），全班组按它依次推进；`checkpoint` 命令逐块记录"经用户查验通过"，用户摇头即做阶段性重构，未查验的块拦在发布门之外
- **安全与隐私工程师（sec）**——有用户数据的项目必配：产出《07-安全与隐私清单》（数据分级/存储传输/攻击面/隐私底线/风险与缓解），严重问题一票缓发；verify 强制密码哈希/登录/备份等安全底线
- **大厂班组协同**——主对话担任项目经理（PMO），下辖产品部/设计部/技术部/质量部/安全部；xl 规模开发拆**前端 + 后端**两岗。职责边界矩阵（主责/知情/禁入）、决策权速查、退回机制三张表规范"各司其职"
- **机器门禁**——`pm.py` 提供 `init / status / dispatch / probe / verify / gate / release` 八个命令：派工单自动携带岗位边界与类型增量并留痕；G1~G4 评审门做机器校验（PRD 章节完整性、验收标准 AC 在设计→自查→测试三层追溯、严重 bug 拦截、**分类型的交付物检查**：网页自包含 / 脚本双击件与编码 / 后台密码加密·登录·备份）
- **高审美 + 重体验**——设计师动笔前用 WebSearch 做**趋势侦察**；审美基准（1 主色+1 强调色、对比度 ≥ 4.5:1、8pt 网格、动效 150~250ms）与体验自查逐项落值；**防 AI 味设计基线**（参考 ibelick/ui-skills 方法论本地化：禁渐变禁发光、动效只动 transform/opacity、结构骨架、空状态一个明确下一步、可访问性优先级表）逐维落值进 02 并机器校验；走查用**三证明审计法**（合同/运行时/修正）杜绝凭感觉报缺陷；商用前台固化为**设计令牌**（CSS 变量全站取值）；素材只用自绘 SVG 或宽松许可证内联，不侵权
- **专业选型**——交付形态 A（单文件网页）/ B（多页文件夹）/ C（Python 脚本）/ **E（本地服务 + SQLite）** + D 原则（公网与跨互联网同步第一版不做）；管理后台默认走 E，以 `assets/admin-template.py` 为骨架（登录/会话/角色权限/备份开箱即用）；对照能力边界表逐条核对需求
- **双击即用**——所有类型都保持"双击就能用"：网页双击 html、脚本和后台双击 启动.bat（后台自动打开浏览器）；数据脚本保证原始文件只读、结果写新文件
- **全程留痕**——派工单与汇报、评审门结果、发布记录全部落盘，换会话/换人接手跑一句 `status` 即恢复现场

## 工作流程

```
用户（甲方，只对接项目经理）
        │
   项目经理 PMO（主对话）
        │
 ┌───┴────┬──────────┬─────────┐
产品部   设计部      技术部      质量部
PM      设计师     TL+fe/be+开发  测试

服务边界判定（合法用途才开工）→ 阶段0 复述确认 + 归类类型（tool/data/admin/front）
        └→ 需求清晰？─ 清晰 → 阶段1 需求+积木块规划 ─G1→ 阶段2 设计 ─G2→ 阶段3 拼块+逐块用户查验(checkpoint) ─G3→ 阶段4 安全审查+测试 ─G4→ release → 阶段5 部署与发布（用户自愿）
           半清晰 → 探索模式：痛点翻译 → 选方向 → 样品(probe) → 回主流程
           模糊+小工具 → 直接做保守 MVP（1 个核心动作），从真实使用中收敛需求

每道门 = pm.py gate 机器校验（按类型查章节，通过自动推进状态机）+ PMO 判断性评审 + 用户确认
```

## 安装

前置：支持 Agent Skills（`SKILL.md`）格式的 agent 环境（如 ZCode）；Python 3.10+ 可选——`pm.py` 为纯标准库，无 Python 时技能内置手动兜底流程。

```bash
# 克隆到用户级技能目录（所有项目可用）
git clone https://github.com/<你的用户名>/idea-to-app.git ~/.agents/skills/idea-to-app
```

Windows 用户也可直接下载 ZIP 解压到 `C:\Users\<你>\.agents\skills\idea-to-app\`。

## 快速开始

装好后开个新对话，直接像聊天一样说：

```
我不会编程，想给我妈做个记买菜账的小工具，她不识几个字，最好一点就能记
```

你会经历：它复述确认 → 给你带选项的问题（或探索模式的方向故事/样品）→ 大白话蓝图确认 → 它开始做并自报进度 → 桌面出现 `买菜记账.html` 和《使用说明.txt》。

其他类型的项目直接说需求即可，它会自动归类：

```
帮我做个小程序，把文件夹里几百张照片按拍摄日期自动改名整理
（→ 数据脚本：交付 .py + 启动.bat，原始照片不会被改动）

我们店三四个人要用一个系统记每天的销售，各有各的账号，只有我能删东西改价格
（→ 管理后台：双击启动、浏览器自动打开、账号登录、角色权限）

我想给我的花店做个官网，顾客手机上看了愿意打电话订花
（→ 商用前台：多页网站 + 设计令牌 + 手机自适应）
```

想继续之前的项目，带上路径说一句即可：

```
用 idea-to-app 继续做 C:\Users\<你>\Desktop\买菜记账，先看看进度
```

## pm.py 命令

```bash
python "<技能目录>/scripts/pm.py" <子命令>
```

| 命令 | 作用 |
|---|---|
| `init <应用名> [--type tool\|data\|admin\|front] [--scale small\|medium\|large\|xl] [--no-data]` | 建项目：目录结构 + **按类型选模板** + 状态机（xl 编制开发拆前后端两岗） |
| `status` | 查看类型/阶段/迭代/评审门/bug（接手项目第一步） |
| `dispatch pm\|design\|tl\|dev\|fe\|be\|sec\|qa` | 生成岗位派工单（自动携带职责边界、退回规则与**类型增量**）并留痕 |
| `probe <样品.html> --label "方案A-大按钮"` | 给样品打"仅方向参考"横幅并归档到 `探索/` |
| `checkpoint M1 --note "..."` | 记录一块积木"经用户查验通过"（先机器校验该块 AC 已全部打勾） |
| `gate G1\|G2\|G3\|G4` | 评审门机器校验（AC 追溯、严重 bug、类型化章节；G2 查规划覆盖、G4 查全部块经用户查验 + 安全清单） |
| `verify` | 交付物静态检查，按类型分派：网页自包含 / 脚本双击件与编码处理 / 后台密码加密·登录·备份 |
| `release --note "..."` | 发版（硬性要求本轮已过 G3），写入发布记录，迭代 +1 |

## 项目结构

```
idea-to-app/
├── SKILL.md                  # 流程手册：服务边界 + 四类画像 + 五阶段 + 积木式推进 + 组织原则 + 沟通铁律
├── scripts/pm.py             # 项目经理执行器（纯标准库，类型化门禁与检查）
├── assets/
│   ├── app-template.html     # 网页样板：自包含/中文/大按钮/备份恢复骨架
│   ├── admin-template.py     # 后台骨架（方案 E）：登录/会话/角色权限/增删改查/备份，纯标准库
│   └── templates/            # 文档模板：00-规划书/01-06 + 07-安全清单 + data/ admin/ front/ 类型差异版
└── references/
    ├── project-types.md      # 四类项目手册：归类判定/阶段差异/AC 写法/红线/常见坑
    ├── team-roles.md         # 职责边界矩阵 + 角色卡（含 fe/be） + 退回机制 + 派工模板
    ├── tech-recipes.md       # 交付形态 A/B/C/E + D 原则 + 数据层/组件/能力边界/性能预算
    ├── deploy-recipes.md     # 阶段 5 部署手册：按类型的部署选项/代价/分步方案/上线检查清单
    ├── design-baseline.md    # 防 AI 味设计基线：可审计的禁令清单 + AI 味速查表 + 三证明审计法
    └── phrasebook.md         # 各阶段话术 + 探索模式 + 积木查验/部署/拒绝话术
```

## 设计原则

1. **判断归模型，机械归脚本**——需求翻译、设计、写代码是判断类工作；建项目、校验门禁、查追溯是机械类工作，必须走 `pm.py`，不靠模型自觉
2. **先归类，再开工**——类型只改各阶段的侧重，不改五阶段、四道门与沟通铁律；拿不准默认 tool
3. **边界即规范**——每岗有禁入清单；xl 前后端分岗后"界面归前端、校验归后端"的分界不得混淆；下游发现上游问题走退回单，禁止静默修改
4. **门禁以脚本输出为准**——机器查格式与追溯，人（PMO+用户）判断质量与真伪
5. **对用户说人话**——术语禁令只约束用户边界，内部文档越专业越好
6. **流程为人服务**——用户答不上来时换选项、上样品、给默认值，绝不追问第三次

## 适用与限制

- 🛡️ **服务边界**：只帮合法正当用途（自用工具、自家生意、有权处理的数据）；破解、扒隐私、钓鱼、恶意软件、批量骚扰等一律婉拒并给合法替代方向——这条优先于一切流程
- ✅ 单机工具类（记账、清单、提醒、查询、资料整理、小游戏）
- ✅ 数据脚本（批量整理文件、生成报表、定时任务；原始文件只读、结果写新文件）
- ✅ 管理后台（多角色、要登录、数据集中；本地服务形态，同一 WiFi 可访问；密码加密存储）
- ✅ 商用级前台（多页官网/活动站：设计令牌、响应式、404 与加载态、内容素材清单）
- ⛔ 刻意第一版不做：公网部署、云账号、跨互联网同步（商用前台的"发布到网上"是正常迭代项，到时带用户操作；本地先行，列入版本规划）
- 管理后台形态限本机/可信内网（无 HTTPS/CSRF 防护）；浏览器双击场景做不了系统通知、摄像头、推送、定位（技术方案阶段核对能力边界并给替代形态）
