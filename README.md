# idea-to-app · 从想法到应用

> 面向零编程经验用户的工程化 Agent Skill：把一句模糊的想法，一步步变成**双击就能用**的应用。
>
> An engineering-grade agent skill that turns a vague idea from a non-programmer into a working, double-click-to-use application — through a simulated big-tech dev team with machine-enforced quality gates.

## 它解决什么问题

零编程经验的人想做自己要用的软件，通常卡在三件事上：

| 痛点 | idea-to-app 的应对 |
|---|---|
| 听不懂术语，答不了技术问题，容易被吓退 | **说人话承诺**：用户边界零术语；技术决策由班组替用户拿主意，只问"你会怎么用" |
| 说不清需求——只有痛点，没有方案，看到东西才知道要不要 | **探索模式**：痛点翻译成 2~3 个解决方向故事 → 选方向 → 做带水印的样品让用户挑 → 替用户拿主意但随时可改 |
| 一次性生成的应用质量不可控、没法验证 | **工程化流水线**：状态机 + 四道机器评审门 + AC 追溯校验，未经门禁不许交付 |

## 核心特性

- **大厂班组协同**——主对话担任项目经理（PMO），下辖产品部/设计部/技术部/质量部。职责边界矩阵（主责/知情/禁入）、决策权速查、退回机制三张表规范"各司其职"
- **机器门禁**——`pm.py` 提供 `init / dispatch / gate / verify / release` 七个命令：派工单自动携带岗位边界并留痕；G1~G4 评审门做机器校验（PRD 章节完整性、验收标准 AC 编号在设计→自查→测试三层追溯、严重 bug 拦截、交付物静态检查）
- **高审美 + 重体验**——设计师动笔前用 WebSearch 做**趋势侦察**（采纳主流手法、不照搬产品）；审美基准（1 主色+1 强调色、对比度 ≥ 4.5:1、8pt 网格、动效 150~250ms）与体验自查（即时反馈、危险操作确认、触摸目标 ≥ 44px）逐项落值；素材只用自绘 SVG 或宽松许可证内联，不侵权
- **专业选型**——技术负责人按数据量定架构与数据层（localStorage / IndexedDB / JSON / SQLite）；需要图表/图标时下载发行文件**本地引用**（记许可证，禁 CDN 外链）；对照 `file://` 能力边界表逐条核对需求，避免"选完才发现做不了"
- **双击即用**——默认交付单文件网页应用：自包含、中文界面、大按钮、自带导出/备份与恢复，用户不装任何东西
- **全程留痕**——派工单与汇报、评审门结果、发布记录全部落盘，换会话/换人接手跑一句 `status` 即恢复现场

## 工作流程

```
用户（甲方，只对接项目经理）
        │
   项目经理 PMO（主对话）
        │
 ┌───┴────┬──────────┬─────────┐
产品部   设计部      技术部      质量部
PM      设计师      TL+开发     测试

阶段0 复述确认 ──→ [需求清晰？]
                    ├─ 清晰 ──────────→ 阶段1 需求 ─G1→ 阶段2 设计 ─G2→ 阶段3 开发+走查 ─G3→ 阶段4 测试 ─G4→ release
                    ├─ 半清晰 ─→ 探索模式：痛点翻译 → 选方向 → 样品(probe) → 回主流程
                    └─ 模糊+小工具 → 直接做保守 MVP（1 个核心动作），从真实使用中收敛需求

每道门 = pm.py gate 机器校验（通过自动推进状态机）+ PMO 判断性评审 + 用户确认
```

## 安装

前置：支持 Agent Skills（`SKILL.md`）格式的 agent 环境（如 ZCode）；Python 3.10+ 可选——`pm.py` 为纯标准库，无 Python 时技能内置手动兜底流程。

```bash
# 克隆到用户级技能目录（所有项目可用）
git clone https://github.com/<你的用户名>/idea-to-app.git ~/.agents/skills/idea-to-app
```

Windows 用户也可直接下载 ZIP 解压到 `C:\Users\<你>\.agents\skills\idea-to-app\`。

## 快速开始

装好后开个新对话，直接像聊天一样说：

```
我不会编程，想给我妈做个记买菜账的小工具，她不识几个字，最好一点就能记
```

你会经历：它复述确认 → 给你带选项的问题（或探索模式的方向故事/样品）→ 大白话蓝图确认 → 它开始做并自报进度 → 桌面出现 `买菜记账.html` 和《使用说明.txt》。

想继续之前的项目，带上路径说一句即可：

```
用 idea-to-app 继续做 C:\Users\<你>\Desktop\买菜记账，先看看进度
```

## pm.py 命令

```bash
python "<技能目录>/scripts/pm.py" <子命令>
```

| 命令 | 作用 |
|---|---|
| `init <应用名> --scale small\|medium\|large [--no-data]` | 建项目：目录结构 + 全套模板 + 状态机 |
| `status` | 查看阶段/迭代/评审门/bug（接手项目第一步） |
| `dispatch pm\|design\|tl\|dev\|qa` | 生成岗位派工单（自动携带职责边界与退回规则）并留痕 |
| `probe <样品.html> --label "方案A-大按钮"` | 给样品打"仅方向参考"横幅并归档到 `探索/` |
| `gate G1\|G2\|G3\|G4` | 评审门机器校验（AC 追溯、严重 bug、外链资源、备份能力…） |
| `verify` | 交付物静态检查：自包含、charset、备份按钮、CSS 外链 |
| `release --note "..."` | 发版（硬性要求本轮已过 G3），写入发布记录，迭代 +1 |

## 项目结构

```

├── SKILL.md                  # 流程手册：五阶段 + 探索模式 + 组织原则 + 沟通铁律

├── assets/

│   └── templates/            # PRD/设计/技术方案/测试报告/发布记录/自查清单/使用说明
└── references/
    ├── team-roles.md         # 职责边界矩阵 + 角色卡 + 退回机制 + 派工模板
    ├── tech-recipes.md       # 交付形态 ABCD + 数据层/本地组件/能力边界/性能预算

```

## 设计原则

1. **判断归模型，机械归脚本**——需求翻译、设计、写代码是判断类工作；建项目、校验门禁、查追溯是机械类工作，必须走 `pm.py`，不靠模型自觉
2. **边界即规范**——每岗有禁入清单；下游发现上游问题走退回单，禁止静默修改
3. **门禁以脚本输出为准**——机器查格式与追溯，人（PMO+用户）判断质量与真伪
4. **对用户说人话**——术语禁令只约束用户边界，内部文档越专业越好
5. **流程为人服务**——用户答不上来时换选项、上样品、给默认值，绝不追问第三次

## 适用与限制

- ✅ 最适合：单机工具类应用（记账、清单、提醒、查询、资料整理、小游戏）
- ⛔ 刻意第一版不做：多设备同步、多人协作、账号系统（先给单机版用起来，联网功能列入版本规划）
- 浏览器双击场景做不了：系统通知、摄像头、推送、定位（技术方案阶段会核对能力边界并给替代形态）
