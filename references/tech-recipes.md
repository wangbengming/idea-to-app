# 交付形态选型手册

本手册是**技术负责人岗位**的决策依据（中小项目由项目经理兼任该岗时同样照此执行）。

选型总原则：**用户从"想用"到"用上"之间的步骤，每多一步就流失一批人。** 在两个都能用的方案之间，永远选交付步骤更少的那个。所有选型由你决定，不要向用户提问技术选项；如果成本差异会影响用户体验（比如需要安装软件），用大白话告诉用户"这一步要做什么"即可。

## 方案 A：单文件网页应用（默认首选）

**适合**：记账、清单、笔记、提醒、倒计时、换算、查询、资料整理、小游戏等"打开就用"的工具。能覆盖大多数初始想法。

**形态**：一个 `.html` 文件包含全部界面和逻辑，用户双击就能在浏览器打开，无需安装任何东西。

**数据**：存在浏览器本地（localStorage）。必须提供：
- "备份"按钮：把数据导出成一个文件（JSON 或 CSV）下载
- "恢复"按钮：从备份文件把数据导回来
- 交付说明里提醒：**别移动或改名这个文件，否则之前记的数据会看不到**（数据跟文件位置绑定）；数据重要的话，定期点一次备份

**自测**：用 browser-use 打开该文件的 file:// 路径，走完主流程：新增 → 查看 → 修改 → 删除 → 备份导出 → 刷新页面后数据还在 → 恢复导入。有任何一步卡住，修完再重测。

## 方案 B：文件夹网页（多页面/内容型）

**适合**：内容较多、需要多个页面（如产品手册、课程资料、图集）的应用。

**形态**：一个文件夹，`index.html` 是入口，其他页面和资源放同文件夹。仍然双击 `index.html` 打开。交付时把整个文件夹打包/告诉用户"整个文件夹别拆开"。

**自测**：同方案 A，且每一页都要点一遍、每个跳转都要走一遍。

## 方案 C：Python 脚本 + 双击启动

**适合**：浏览器做不到的事——批量处理电脑里的文件（改名、整理照片、格式转换）、定时任务、抓取网页信息等。

**形态**：脚本 + 一个 `启动.bat`，用户双击 bat 就运行。bat 内容形如：

```bat
@echo off
chcp 65001 >nul
cd /d "%~dp0"
python 我的工具.py
pause
```

（`cd /d "%~dp0"` 让脚本无论从哪里双击都能找到同文件夹的资源；`pause` 让窗口在结束后停留，用户能看到结果而不是一闪而过。）

**界面**：优先 tkinter（系统自带，用户无需安装）；或让脚本在浏览器里出界面（起本地服务后用 `webbrowser.open()` 自动打开页面）。后者体验更好时优先。

**前置检查**：动手前先跑 `python --version` 确认用户电脑装了 Python。没有的话，用大白话告诉用户"需要先装一个小软件，我会带你装"，给出 python.org 下载链接，并特别提醒安装时勾选 **Add to PATH**（"勾上这个小勾勾，以后就能双击使用了"）。

**自测**：真实运行一遍主流程（造几个测试文件跑一遍），确认输出和提示信息都是中文、看得懂。

## 方案 D：需要服务器/多人/账号——第一版不做

**适合判断**：多设备同步、多人协作、账号登录、随时随地在手机访问。

**原则**：第一版不做。给用户单机替代方案先跑起来（数据导出导入文件，也算一种"同步"），把联网功能列入"以后再说"，并解释："第一版先在你自己电脑上用顺，以后想在家里其他设备也能看，我们再加那个功能。"如果用户坚持要，说明代价（需要一台一直开着的电脑，或在网上租一台），确认后再继续。

## 决策速查

| 用户想要 | 选 |
|---|---|
| 记账/清单/提醒/查询/小工具/小游戏 | A |
| 多页面的资料/展示型应用 | B |
| 整理电脑文件/批量改名/定时抓取 | C |
| 手机随时用/多人共用/要登录 | 先 D 的单机替代，迭代时再议 |
| 需要图表/图标/字体 | 本地化第三方文件（查许可证），禁 CDN 外链 |
| 拿不准 | A（步骤最少） |

## 架构与数据层深化（技术负责人用）

交付形态（A/B/C）定了之后，还要定数据层与组件策略：

| 数据形态 | 选 |
|---|---|
| 键值型小数据（几百条以内） | localStorage（方案 A 默认） |
| 结构复杂、条目多（超 5MB 或 1000 条） | IndexedDB（仍然零依赖、零安装） |
| Python 侧数据 | JSON 文件；多表或要查询 → SQLite（标准库自带） |

## 本地第三方组件（打破"零依赖"的正确姿势）

默认零依赖。确需图表、图标等能力时：**下载发行文件放进应用文件夹本地引用**（如 Chart.js 的 UMD 单文件），双击打开仍然零网络依赖。规则：

- 只用宽松许可证（MIT / ISC / Apache-2.0 / CC0），组件名、版本、许可证记入 03-技术方案
- 严禁 CDN 外链（verify 会拦截）；字体一律系统字体栈
- 图标优先自绘 SVG 内联，其次内联开源图标（Tabler、Feather 等 MIT 协议）

## 双击网页（file://）能力边界表

方案 A/B 在浏览器里以 file:// 打开，能力有边界。技术负责人必须在方案里逐条核对 PRD，不要选了方案 A 才发现功能做不了：

| 能力 | file:// 下 |
|---|---|
| localStorage / IndexedDB、音频播放、拖拽、全屏、打印 | ✅ 可用 |
| 页面内提醒（大字提示 + 声音 + 标题闪烁） | ✅ 可用（提醒类需求的默认替代） |
| 系统通知、摄像头/麦克风、地理定位、推送、跨设备同步 | ❌ 不可用（需 https 或服务端）——第一版不做或换形态 |

## 性能预算

列表超 1000 条 → 分页或虚拟滚动；数据超 5MB → 换 IndexedDB；单文件超 1MB 考虑拆分。本地文件打开天然快，**不要为"性能"引入框架**。
