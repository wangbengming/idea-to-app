# 交付形态选型手册

本手册是**技术负责人岗位**的决策依据（中小项目由项目经理兼任该岗时同样照此执行）。项目类型（tool/data/admin/front）的归类与流程差异见 `references/project-types.md`。

选型总原则：**用户从"想用"到"用上"之间的步骤，每多一步就流失一批人。** 在两个都能用的方案之间，永远选交付步骤更少的那个。所有选型由你决定，不要向用户提问技术选项；如果成本差异会影响用户体验（比如需要安装软件），用大白话告诉用户"这一步要做什么"即可。

## 方案 A：单文件网页应用（默认首选）

**适合**：记账、清单、笔记、提醒、倒计时、换算、查询、资料整理、小游戏等"打开就用"的工具。能覆盖大多数初始想法。

**形态**：一个 `.html` 文件包含全部界面和逻辑，用户双击就能在浏览器打开，无需安装任何东西。

**数据**：存在浏览器本地（localStorage）。必须提供：
- "备份"按钮：把数据导出成一个文件（JSON 或 CSV）下载
- "恢复"按钮：从备份文件把数据导回来
- 交付说明里提醒：**别移动或改名这个文件，否则之前记的数据会看不到**（数据跟文件位置绑定）；数据重要的话，定期点一次备份

**自测**：用 browser-use 打开该文件的 file:// 路径，走完主流程：新增 → 查看 → 修改 → 删除 → 备份导出 → 刷新页面后数据还在 → 恢复导入。有任何一步卡住，修完再重测。

## 方案 B：文件夹网页（多页面/内容型）

**适合**：内容较多、需要多个页面（如产品手册、课程资料、图集）的应用。

**形态**：一个文件夹，`index.html` 是入口，其他页面和资源放同文件夹。仍然双击 `index.html` 打开。交付时把整个文件夹打包/告诉用户"整个文件夹别拆开"。

**自测**：同方案 A，且每一页都要点一遍、每个跳转都要走一遍。

## 方案 C：Python 脚本 + 双击启动

**适合**：浏览器做不到的事——批量处理电脑里的文件（改名、整理照片、格式转换）、定时任务、抓取网页信息等。

**形态**：脚本 + 一个 `启动.bat`，用户双击 bat 就运行。bat 内容形如：

```bat
@echo off
chcp 65001 >nul
cd /d "%~dp0"
python 我的工具.py
pause
```

（`cd /d "%~dp0"` 让脚本无论从哪里双击都能找到同文件夹的资源；`pause` 让窗口在结束后停留，用户能看到结果而不是一闪而过。）

**界面**：优先 tkinter（系统自带，用户无需安装）；或让脚本在浏览器里出界面（起本地服务后用 `webbrowser.open()` 自动打开页面）。后者体验更好时优先。

**前置检查**：动手前先跑 `python --version` 确认用户电脑装了 Python。没有的话，用大白话告诉用户"需要先装一个小软件，我会带你装"，给出 python.org 下载链接，并特别提醒安装时勾选 **Add to PATH**（"勾上这个小勾勾，以后就能双击使用了"）。

**自测**：真实运行一遍主流程（造几个测试文件跑一遍），确认输出和提示信息都是中文、看得懂。

## 方案 D：需要公网/跨设备同步——第一版不做

**适合判断**：跨互联网的多设备同步、公网访问、云账号。

**原则**：第一版不做。给用户单机替代方案先跑起来（数据导出导入文件，也算一种"同步"），把联网功能列入"以后再说"，并解释："第一版先在你自己电脑上用顺，以后想在家里其他设备也能看，我们再加那个功能。"如果用户坚持要，说明代价（需要一台一直开着的电脑，或在网上租一台），确认后再继续。

**例外**：管理后台类（admin）的"几个人分角色用"走**方案 E 本地服务**——它不需要公网，是本手册的正常交付形态，不套用本条。"同一 WiFi 下的手机/电脑访问"由方案 E 的局域网能力覆盖，也不算跨设备同步。

## 方案 E：本地服务应用（管理后台默认形态）

**适合**：几个人到几十个人分角色录入/管理一批资料，要登录、数据集中放（进销存、台账、客户资料）。项目类型 admin 的默认形态。

**形态**：Python 起一个本地小服务（**标准库 http.server，不装任何东西**），双击 `启动.bat` → 服务运行 + 浏览器自动打开页面。关掉那个黑窗口，系统就停了。对用户的说法："双击『启动』，浏览器自动打开你们的系统；关掉窗口就是关系统。"

**数据**：单文件 SQLite（`data.db`）。必须提供：
- 界面"备份数据"按钮：把数据文件复制到 `backups/` 文件夹（带时间戳）
- 恢复 = 关服务后把备份文件改回 `data.db`（写进使用说明）
- 交付说明提醒：数据文件别删；"复制一份数据文件出去，就是备份"

**骨架**：`assets/admin-template.py`——登录/退出/改密、pbkdf2 密码哈希、会话 Cookie、按角色的服务端权限校验、示例实体的增删改查+搜索+分页、用户管理、备份按钮，全部内置。开发以其为起点扩展，不推倒重写；换型需在 03-技术方案 写明理由与代价。

**局域网访问**：默认只监听本机（`HOST = "127.0.0.1"`）。用户要"店里其他电脑/手机也能用"时，把 HOST 改为 `"0.0.0.0"`，同一 WiFi 的设备用"那台电脑的 IP:端口"打开。对用户说："同一个路由器的设备都能打开，外面的网络不行。"改动写进 03-技术方案 与使用说明。

**安全底线**（verify 强制检查前三条）：
- 密码必须 pbkdf2/哈希存储，禁止明文
- 每个路由在服务端校验角色（界面藏菜单只是呈现）
- 备份能力必须存在；内置管理员账号首次登录强制提示改密；登录失败限速
- 本形态**无 HTTPS、未做 CSRF**：只限本机/可信内网使用，要公网属形态升级（列入"以后再说"），并在使用说明提醒"别把端口暴露到外面网络"

**自测**：真实启动 → 登录 → 增删改查 → 备份 → 重启服务数据还在 → 用无权限账号直接访问受限地址（应被服务端拒绝）。

**前置检查**：同方案 C（`python --version`）。

## 决策速查

| 用户想要 | 选 |
|---|---|
| 记账/清单/提醒/查询/小工具/小游戏 | A |
| 多页面的资料/展示型应用 | B |
| 给客户看的官网/门店页/活动页（要好看要专业） | B+（方案 B 升级，见"商用前台要点"） |
| 整理电脑文件/批量改名/定时抓取/生成报表 | C |
| 几个人分角色管理资料、要登录（后台） | E |
| 公网部署/跨互联网同步/云账号 | 先 D 的单机替代，迭代时再议 |
| 需要图表/图标/字体 | 本地化第三方文件（查许可证），禁 CDN 外链 |
| 拿不准 | A（步骤最少） |

## 架构与数据层深化（技术负责人用）

交付形态（A/B/C/E）定了之后，还要定数据层与组件策略：

| 数据形态 | 选 |
|---|---|
| 键值型小数据（几百条以内） | localStorage（方案 A 默认） |
| 结构复杂、条目多（超 5MB 或 1000 条） | IndexedDB（仍然零依赖、零安装） |
| Python 侧数据 | JSON 文件；多表或要查询 → SQLite（标准库自带） |
| 管理后台（方案 E） | SQLite 单文件 data.db + backups/ 备份（骨架已内置） |

## 本地第三方组件（打破"零依赖"的正确姿势）

默认零依赖。确需图表、图标等能力时：**下载发行文件放进应用文件夹本地引用**（如 Chart.js 的 UMD 单文件），双击打开仍然零网络依赖。规则：

- 只用宽松许可证（MIT / ISC / Apache-2.0 / CC0），组件名、版本、许可证记入 03-技术方案
- 严禁 CDN 外链（verify 会拦截）；字体一律系统字体栈
- 图标优先自绘 SVG 内联，其次内联开源图标（Tabler、Feather 等 MIT 协议）

## 双击网页（file://）能力边界表

方案 A/B 在浏览器里以 file:// 打开，能力有边界。技术负责人必须在方案里逐条核对 PRD，不要选了方案 A 才发现功能做不了：

| 能力 | file:// 下 |
|---|---|
| localStorage / IndexedDB、音频播放、拖拽、全屏、打印 | ✅ 可用 |
| 页面内提醒（大字提示 + 声音 + 标题闪烁） | ✅ 可用（提醒类需求的默认替代） |
| 系统通知、摄像头/麦克风、地理定位、推送、跨设备同步 | ❌ 不可用（需 https 或服务端）——第一版不做或换形态 |

方案 E（localhost）不受 file:// 限制：服务端能读写文件、集中存数据、局域网互访；但系统通知、摄像头等浏览器能力同样受 https/权限限制，仍按保守清单核对。

## 数据脚本实现要点（方案 C 深化）

- **编码链**：读文件依次试 utf-8 → gbk → utf-16（或 `errors="replace"` + 中文提示"这个文件的编码有点特殊"）；输出统一 utf-8，**给 Excel 用的 csv 必须 utf-8-sig**（否则 Excel 打开中文乱码）。
- **原始文件神圣**：只读输入；输出写新文件或加后缀（`_汇总.csv`）；同名结果已存在 → 提示或自动加序号，**绝不静默覆盖**。
- **原子写**：先写 `.tmp` 再改名替换，中途失败不留半个坏文件。
- **大文件流式**：逐行/分块处理，不一次读进内存；量级特别大时分批跑。
- **中文交互**：进度（"第 2/5 个…"）、结果（"完成！共 128 行，结果在…"）、报错（哪里错了、跳过了什么、结果在哪）全部中文；窗口结尾 `pause` 不闪退。
- **第三方库**：标准库优先（csv/json/re/sqlite3/datetime/pathlib 几乎够用）；确需 pandas/openpyxl/Pillow → 记录名称/版本/许可证，并附"安装依赖.bat"（`pip install xxx` + 中文提示），使用说明写"第一次用前先双击安装"。

## 商用前台要点（方案 B 升级为 B+）

- **结构**：多页 HTML（页面简单直接）或单页 hash 路由（交互多时）；**不引框架、不用构建工具**，除非写明不可替代理由。公共头尾一处定义——页数 > 5 用几行 JS 注入公共导航，避免逐页手改失同步。
- **设计令牌**：02 的色板/字阶/间距/圆角/阴影固化成 `:root` CSS 变量，全站只引用变量不写裸值；这是"商用级观感稳定"的技术落点。
- **商用清单**（逐项落实）：每页 `<title>` 与 `<meta description>` 各不相同、favicon（内联 SVG data URI）、404 页、加载与空状态、图片懒加载（`loading="lazy"`）+ 宽高属性防跳动 + 压缩、`tel:` 拨号链接、打印样式（如需要）。
- **性能预算**：单页 HTML+CSS+JS < 1MB；首屏图片 < 500KB；本地打开天然快，不为性能引框架。
- **内容先行**：文字与图片素材阶段 1 就跟用户要（PRD 素材清单），素材不齐不进入收尾；版权自查（用户素材/自绘/宽松许可）记录进 03-技术方案。
- **以后放网上**：静态文件夹可直接托管到任意静态空间（GitHub Pages、各家对象存储）；第一版本地验收，发布属正常迭代，全程带用户操作账号注册。

## 性能预算

列表超 1000 条 → 分页或虚拟滚动；数据超 5MB → 换 IndexedDB；单文件超 1MB 考虑拆分。本地文件打开天然快，**不要为"性能"引入框架**。
