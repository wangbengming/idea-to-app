# 交付形态选型手册

本手册是**技术负责人岗位**的决策依据（中小项目由项目经理兼任该岗时同样照此执行）。项目类型（tool/data/admin/front）的归类与流程差异见 `references/project-types.md`。

选型总原则：**用户从"想用"到"用上"之间的步骤，每多一步就流失一批人。** 在两个都能用的方案之间，永远选交付步骤更少的那个。所有选型由你决定，不要向用户提问技术选项；如果成本差异会影响用户体验（比如需要安装软件），用大白话告诉用户"这一步要做什么"即可。

## 现代技术栈基线（硬约束，先于一切选型）

技术栈必须是**当前主流的做法，按实际需求做最优选择**。"零构建、双击交付"既不是退回过时技术的理由，也不是手搓一切的理由——选型的第一反应是找现成开源方案**拿来二开**（见下文「开源优先」节），现代原生只在没有合身轮子时登场。两层约束：

**机器拦截层（verify 直接打回，不商量）**：交付物 HTML 里出现以下特征即打回——`jquery`（含脚本引用）、jQuery 独有签名（`$.ajax(` / `$.get(` / `$.post(` / `$.fn.` / `$(document).ready`）、`XMLHttpRequest`、`document.write(`、**系统弹窗调用（`confirm(` / `alert(` / `prompt(`——教学注释除外，机器先剥注释再查）**、**内联事件（`onclick=` 等拼在标签或模板字符串里）**、**`var` 声明**、**`debugger` 语句**；另有提醒级：`console.log` 类调试输出残留。替代：jQuery → 原生 DOM API（`querySelector`/`classList`）；`XMLHttpRequest` → `fetch` + `async/await`；`document.write` → 模板字符串 + `textContent`/`innerHTML`；系统弹窗 → 页面内 toast/撤销条/`<dialog>`；内联事件 → `addEventListener`/事件委托；`var` → `const`/`let`。注意：裸 `$(...)` **不拦**——现代常有人写 `const $ = q => document.querySelector(q)` 简写，属合法主流。

**评审判断层（技术负责人动笔前逐项过）**：

- JS：`const`/`let`（不用 `var`）、箭头函数、`async/await`、模板字符串、`addEventListener`（不以内联 `onclick` 为主要事件架构）。
- HTML/CSS：语义化 HTML5 标签；flex/grid 布局（不用 table/float 排版）；CSS 自定义属性承载设计令牌；原生 `<dialog>`/`<details>`/`<input type="date">` 优先于自造轮子。
- 框架策略：**开源优先，拿来二开，按「组件与框架引入阶梯」定级**（见下一节）——先按需求找合身的开源组件库/样板项目，下载发行文件本地引用并做二次开发；手搓只对 L0 级小东西划算，**达到 L2/L3/L4 阈值还坚持全手搓 = 选型事故**，03 选型说明必须答得上"为什么不用现成轮子"。引入框架时选**当前主流大版本**（如 Vue 3.x），禁 CDN、禁已停止维护的大版本。"恰当"指全局最优，不是惯性地自己写，也不是惯性地不用轮子。
- Python：3.10+ 风格（f-string、pathlib、dataclasses）；**标准库优先的路线不变**——`http.server`/`sqlite3` 是"零安装的恰当选择"，不属于过时技术，不为赶时髦引入安装负担。
- file:// 注意：跨文件的 ES module `import` 在 file:// 下被浏览器拦截——单文件内联脚本不受影响；方案 B 的公共 JS 用普通 `<script>` 或内联注入（与"公共导航 JS 注入"做法一致），交付前必须真实双击验证。
- 每次选型在 03-技术方案 的「选型说明」节写明**选型原因**，四要素缺一不可：① 结论——选了什么（含框架/组件引入到阶梯的哪一级 L0~L4）；② 需求匹配点——正好接住 PRD 哪几条、为什么对这个需求最合适；③ 主流与维护依据——当前主流大版本、生态成熟，或标准库自带零安装；④ 否决项及原因——至少 1 个被否的方案 + 否决理由（含代价，如"引 React 需构建链，双击交付做不到"）。另起一行写**组件来源**——拿来二开了哪些开源组件/样板（名称/版本/许可证/改了什么）、哪些部分手搓及为什么值得手搓：用现成轮子不需要理由，重造轮子才需要。末尾加一行**大白话版本**（如"做成一个双击就能用的网页，不用装任何东西"）——项目经理会拿它向用户汇报方案并征求意见，用户点头才开工；技术决策不抛给用户，但做成什么样、为什么，要让用户听得懂、点得了头。

## 组件与框架引入阶梯（反手搓条款）

"零构建、双击交付"**不等于"什么都自己写"**。原生手搓只对最简单的项目划算；交互一多，手搓的 DOM 同步代码就是逻辑混乱与"一眼土"的头号来源。按下表定级——**达到阈值还坚持手搓，举证责任反转：必须在 03「选型说明」写明理由**：

| 级 | 触发信号（任一命中即升级） | 引什么 | 参考选项（均 MIT 等宽松许可） |
|---|---|---|---|
| L0 纯手写 | ≤1 个视图、状态变量 ≤2 个、无列表/联动 | 现代原生 HTML/CSS/JS | —— |
| L1 设计系统 | ≥2 个页面/区块，或观感要求高于浏览器默认 | 本地引用成熟 CSS 框架，令牌仍用自己的 `:root` 覆盖 | Pico.css、Bootstrap（本地 css 文件） |
| L2 能力组件 | 需要图表/日历/拖拽/富文本等专门能力；**重计算/多媒体复刻项目（视频编解码、逐帧渲染、音频处理、3D）也在此级** | 对应开源库的本地发行版；重计算类优先浏览器原生能力（WebCodecs/Web Audio/canvas） | Chart.js、ECharts（UMD 单文件）；Three.js（MIT）；视频类能力速查见 `replica-playbook.md` |
| L3 响应式框架 | 联动视图 ≥3 个；或 CRUD 列表+表单+校验同屏；或多步流程/状态分散 | 本地引用现代框架运行时（免构建用法） | Vue 3（`vue.global.prod.js`，百 KB 级）、Preact+htm、Alpine.js |
| L4 组件库 | admin 后台：实体页 ≥3 或交互密集 | L3 框架 + 配套组件库 | Vue 3 + Element Plus（本地文件，含图标） |

**交付形态决定能引什么（唯一硬边界）**：
- **file://（方案 A/B）**：只能引 **UMD/IIFE 单文件发行版**——`<script src="本地路径">` 直接可用；ESM-only 包双击会被浏览器拦（verify 机器拦截 module 引用）。单文件交付时把框架**内联**进 HTML（Vue 3 生产版百 KB 级，本地打开无感知）。框架的无构建用法是完整用法：模板字符串/`template` 选项写组件，不依赖 JSX 与编译。
- **localhost（方案 E）**：浏览器走 http 访问，**无 ESM 限制**——组件库全量包、图标库都能本地 vendor；这是 admin 界面摆脱"手搓感"的正路（骨架照旧零依赖起步，按 03 升级，服务端结构不动）。
- 任何形态：**禁 CDN 外链；构建链只禁用户侧**——开发侧允许用构建工具（vite 等）产出静态产物 `dist/`（E2 前后端分离、专业级前端的主路），交付物必须是免构建可直接运行的形态（dist + 双击启动；file:// 形态须输出无 module 依赖的 legacy/IIFE 产物，verify 会拦；**方案 A 单文件形态若用构建产物，须用 singlefile 类插件内联成单文件**）。用户拿到的永远是零安装、双击即用；被限制的是"用户要装 npm/跑构建"，不是专业开发方式本身。

**手搓失控判负线**（开发期命中任一条 → 停下来按阶梯升级，别硬写）：同一份界面状态存了 ≥2 处靠人肉同步；"当 X 变就改 Y"的级联超过 3 层；列表渲染与筛选/排序/分页全在手写；单个事件处理函数 >50 行还在拼 innerHTML 字符串。

### 主流技术栈速查表（按能力域——"选主流、适配度高"的查表执行）

| 能力域 | 主流选项（引入前逐个过开源四关） |
|---|---|
| 图表 | ECharts、Chart.js |
| 后台组件库（L4/E2） | Element Plus、Naive UI（Vue 3 系）；Ant Design（React 系，需构建） |
| 轻量 CSS 设计系统（L1） | Pico.css、Bootstrap（本地文件） |

| 视频编解码/媒体 | WebCodecs（原生优先）、ffmpeg.wasm（兼容兜底，LGPL 留痕）——见 replica-playbook |
| 3D / 复杂数据可视化 | Three.js、D3 |
| 图标 | Tabler、Feather（MIT，内联） |

**这张表是起点不是终点**：模型的知识有截止日——选定任何一项前，用 WebSearch 查它**当前的大版本、是否仍在维护、有没有更好的新替代**，查证结果（含"未查到"）记进 03 选型说明；查完仍拿不准就选表中该域的第一项。别用过时大版本，也别凭印象把已停维护的库当主流。

## 方案 A：单文件网页应用（默认首选）

**适合**：记账、清单、笔记、提醒、倒计时、换算、查询、资料整理、小游戏等"打开就用"的工具。能覆盖大多数初始想法。

**形态**：一个 `.html` 文件包含全部界面和逻辑，用户双击就能在浏览器打开，无需安装任何东西。

**数据**：存在浏览器本地（localStorage）。必须提供：
- "备份"按钮：把数据导出成一个文件（JSON 或 CSV）下载
- "恢复"按钮：从备份文件把数据导回来
- 交付说明里提醒：**别移动或改名这个文件，否则之前记的数据会看不到**（数据跟文件位置绑定）；数据重要的话，定期点一次备份

**自测**：用 browser-use 打开该文件的 file:// 路径，走完主流程：新增 → 查看 → 修改 → 删除 → 备份导出 → 刷新页面后数据还在 → 恢复导入。有任何一步卡住，修完再重测。

## 方案 B：文件夹网页（多页面/内容型）

**适合**：内容较多、需要多个页面（如产品手册、课程资料、图集）的应用。

**形态**：一个文件夹，`index.html` 是入口，其他页面和资源放同文件夹。仍然双击 `index.html` 打开。交付时把整个文件夹打包/告诉用户"整个文件夹别拆开"。

**自测**：同方案 A，且每一页都要点一遍、每个跳转都要走一遍。

## 方案 C：Python 脚本 + 双击启动

**适合**：浏览器做不到的事——批量处理电脑里的文件（改名、整理照片、格式转换）、定时任务、抓取网页信息等。

**形态**：脚本 + 一个 `启动.bat`，用户双击 bat 就运行。bat 内容形如：

```bat
@echo off
chcp 65001 >nul
cd /d "%~dp0"
python 我的工具.py
pause
```

（`cd /d "%~dp0"` 让脚本无论从哪里双击都能找到同文件夹的资源；`pause` 让窗口在结束后停留，用户能看到结果而不是一闪而过。）

**界面**：优先 tkinter（系统自带，用户无需安装）；或让脚本在浏览器里出界面（起本地服务后用 `webbrowser.open()` 自动打开页面）。后者体验更好时优先。

**前置检查**：动手前先跑 `python --version` 确认用户电脑装了 Python。没有的话，用大白话告诉用户"需要先装一个小软件，我会带你装"，给出 python.org 下载链接，并特别提醒安装时勾选 **Add to PATH**（"勾上这个小勾勾，以后就能双击使用了"）。

**自测**：真实运行一遍主流程（造几个测试文件跑一遍），确认输出和提示信息都是中文、看得懂。

## 方案 D：需要公网/跨设备同步——第一版不做

**适合判断**：跨互联网的多设备同步、公网访问、云账号。

**原则**：第一版不做。给用户单机替代方案先跑起来（数据导出导入文件，也算一种"同步"），把联网功能列入"以后再说"，并解释："第一版先在你自己电脑上用顺，以后想在家里其他设备也能看，我们再加那个功能。"如果用户坚持要，说明代价（需要一台一直开着的电脑，或在网上租一台），确认后再继续。

**例外**：管理后台类（admin）的"几个人分角色用"走**方案 E 本地服务**——它不需要公网，是本手册的正常交付形态，不套用本条。"同一 WiFi 下的手机/电脑访问"由方案 E 的局域网能力覆盖，也不算跨设备同步。

## 方案 E：本地服务应用（管理后台默认形态）

**适合**：几个人到几十个人分角色录入/管理一批资料，要登录、数据集中放（进销存、台账、客户资料）。项目类型 admin 的默认形态。

**形态**：Python 起一个本地小服务（默认标准库 http.server，零安装），双击 `启动.bat` → 服务运行 + 浏览器自动打开页面。关掉那个黑窗口，系统就停了。对用户的说法："双击『启动』，浏览器自动打开你们的系统；关掉窗口就是关系统。"服务端与界面按项目档次升级，见下「服务与界面分级」。

**数据**：单文件 SQLite（`data.db`）。必须提供：
- 界面"备份数据"按钮：把数据文件复制到 `backups/` 文件夹（带时间戳）
- 恢复 = 关服务后把备份文件改回 `data.db`（写进使用说明）
- 交付说明提醒：数据文件别删；"复制一份数据文件出去，就是备份"

**服务与界面分级（商用级路径）**：骨架 `assets/admin-template.py`（登录/退出/改密、pbkdf2 密码哈希、会话 Cookie、按角色的服务端权限校验、示例实体增删改查+搜索+分页、用户管理、备份按钮，全部内置）是零依赖起点，开发以其起步扩展、不推倒重写；按项目档次升级，**换的只是实现方式，安全结构（pbkdf2/服务端角色校验/备份）一档都不能丢**：

| 档 | 什么时候 | 架构 |
|---|---|---|
| E1 骨架直改 | 单实体、界面简单 | admin-template.py 原样扩展（纯标准库，零安装） |
| E2 前后端分离 | 实体页 ≥3、交互密集、观感要商用级——**admin 的默认主路** | 后端仍是骨架（路由改成 JSON API + 静态文件托管，结构不丢）；前端独立工程：组件库（引入阶梯 L4）+ 开发侧构建链产出 `dist/`，交付 = 后端 + dist + 启动.bat，用户仍零安装双击即用 |
| E3 换服务框架 | 需要 websocket、大文件上传、中间件等骨架给不了的能力 | Flask/FastAPI 换型 + 「安装依赖.bat」（pip install + 中文提示，同 data 项目的第三方库策略），03 写明换型理由与代价 |

E2 的要义：界面的专业度来自真正的前端工程（组件库 + 构建），而不是在 Python 字符串里拼 HTML——"单机后台"不是界面将就的理由。档位选择与理由记进 03 选型说明。

**局域网访问**：默认只监听本机（`HOST = "127.0.0.1"`）。用户要"店里其他电脑/手机也能用"时，把 HOST 改为 `"0.0.0.0"`，同一 WiFi 的设备用"那台电脑的 IP:端口"打开。对用户说："同一个路由器的设备都能打开，外面的网络不行。"改动写进 03-技术方案 与使用说明。

**重计算/媒体项目（对标复刻常见）**：形态 E 是这类项目的默认形态——localhost 解锁 worker、多线程 wasm 与 SharedArrayBuffer（需响应头加 COOP/COEP，改造点写进 03），文件读写走本地服务也远快于浏览器沙箱；能力选型与降级方案见 `references/replica-playbook.md`。

**安全底线**（verify 强制检查前三条）：
- 密码必须 pbkdf2/哈希存储，禁止明文
- 每个路由在服务端校验角色（界面藏菜单只是呈现）
- 备份能力必须存在；内置管理员账号首次登录强制提示改密；登录失败限速
- 本形态**无 HTTPS、未做 CSRF**：只限本机/可信内网使用，要公网属形态升级（列入"以后再说"），并在使用说明提醒"别把端口暴露到外面网络"

**自测**：真实启动 → 登录 → 增删改查 → 备份 → 重启服务数据还在 → 用无权限账号直接访问受限地址（应被服务端拒绝）。

**前置检查**：同方案 C（`python --version`）。

## 决策速查

| 用户想要 | 选 |
|---|---|
| 记账/清单/提醒/查询/小工具/小游戏 | A |
| 多页面的资料/展示型应用 | B |
| 给客户看的官网/门店页/活动页（要好看要专业） | B+（方案 B 升级，见"商用前台要点"） |
| 整理电脑文件/批量改名/定时抓取/生成报表 | C |
| 几个人分角色管理资料、要登录（后台） | E |
| 公网部署/跨互联网同步/云账号 | 先 D 的单机替代，迭代时再议 |
| 需要图表/图标/日历等现成能力 | 先找开源组件拿来二开（本地引用 + 许可证留痕），禁 CDN 外链 |
| 交互多、状态联动、列表+表单同屏 | 按「组件与框架引入阶梯」升到 L3/L4——这属于"该用轮子"，不属于"能省则省" |
| 商用级后台界面（实体多/交互密/要门面） | 方案 E → **E2 前后端分离**（骨架做 API+静态托管，前端组件库+构建出 dist，用户仍零安装） |
| 用户提到手机/随时随地用 | 响应式网页（一套码多端），不是只活在某个平台容器里的形态 |
| 用户点名小程序/第三方托管平台 | 先给响应式 H5 替代；确需平台能力才上，03 写依赖风险与迁出路径 |
| 拿不准 | A（步骤最少） |

## 架构与数据层深化（技术负责人用）

交付形态（A/B/C/E）定了之后，还要定数据层与组件策略：

| 数据形态 | 选 |
|---|---|
| 键值型小数据（几百条以内） | localStorage（方案 A 默认） |
| 结构复杂、条目多（超 5MB 或 1000 条） | IndexedDB（仍然零依赖、零安装） |
| Python 侧数据 | JSON 文件；多表或要查询 → SQLite（标准库自带） |
| 管理后台（方案 E） | SQLite 单文件 data.db + backups/ 备份（骨架已内置） |

## 开源优先：拿来二开（选型的第一反应）

动笔前**先做一轮"找现成"**，这是选型的第一步，不是附加题。按需求关键词检索成熟开源方案（图表 → Chart.js / ECharts；样式与组件 → Pico.css / Bootstrap / 开源 HTML 模板；后台界面 → 开源管理模板；Python 侧 → pandas / openpyxl / Pillow 等），候选逐项过四关：

1. **许可证**：只用宽松许可证（MIT / ISC / Apache-2.0 / CC0），不宽松的一律不用；
2. **维护**：当前仍在维护、社区活跃，停止维护的不碰；
3. **兼容交付**：能下载发行文件放应用文件夹**本地引用**，不破坏"双击即用"。判据按形态分：file://（方案 A/B）须选 **UMD/IIFE 发行版**（ESM-only 组件双击被拦，verify 机器拦截 module 引用）；localhost（方案 E）无此限制，组件库全量包照常本地 vendor。**需要 CDN、或只有"装了 npm 才能出产物"一种用法的方案才出局**——大多数主流库都有免构建发行版，先找发行版再下结论，别拿"要构建链"当不找轮子的借口。交付红线不变：严禁 CDN 外链（verify 会拦截）；字体一律系统字体栈；
4. **贴合度**：二开量明显小于手搓量才算合身。

**合身 → 拿来二开**：下载发行文件本地引用，在 03-技术方案 记组件名/版本/许可证/**改了什么**。**不合身 → 手搓**，选型说明写明现成方案为什么不合身——这行字就是"没偷懒"的证据；但先对照「组件与框架引入阶梯」确认自己不是在 L2 以上硬手搓。图标优先自绘 SVG 内联，其次内联开源图标（Tabler、Feather 等 MIT 协议）。

## 体感与交互工艺（代码层——"功能都对、用起来天差地别"的那一层）

界面"功能齐全但体感差"，八成坏在这一节。开发动笔前过一遍，G3 代码走查照此打回：

**响应性铁律**：
- 事件处理函数 **≤16ms（一帧）内让出主线程**：计算重的活分片（`requestAnimationFrame`/`setTimeout` 切块）或 `await` 异步化——主线程一卡，什么设计都白搭；
- 每次点击**先出反馈态再干活**：按下效果/loading 态同帧出现、结果后到；高频操作用乐观更新（先改界面，失败回滚 + 提示）；
- 输入搜索 200~300ms 防抖；**别每敲一个键全量重渲染**。

**原生弹窗禁令**：`confirm` / `alert` / `prompt` 禁止作为正式交互（调试除外）——阻塞式、样式突兀、和页面完全脱节，是体感头号杀手。替代：页面内提示条/`<dialog>`；删除走"撤销提示条"（design-baseline 交互节）。

**事件架构**：事件绑定写在 JS（`addEventListener` / 事件委托），**禁止在 innerHTML 字符串里拼 `onclick`**——拼出来的是状态同步混乱之源（状态在 DOM 里、逻辑在字符串里，改一处漏三处），也是"处理逻辑差"最常见的起点。样板 `assets/app-template.html` 是标准写法。

**动画与过渡**：状态跳变给 150~250ms 过渡（只动 transform/opacity）；列表新增行高亮渐隐、移除行收缩消失；顺序变化用 FLIP。

**加载体感**：等待 >300ms 出骨架（形状 = 内容形状）；≥1 秒出进度且可取消；任何等待界面不许"死"（可点、可返回）。

**键盘与焦点**：表单 Enter 提交、Esc 关弹层、Tab 顺序合理、焦点环可见、弹层焦点圈定关闭归位。

**列表性能**：百条以内的小列表全量重渲染可接受（样板即此写法，别过度工程）；超过 100 条 → 分页/虚拟化，且数据更新做**局部渲染**（或升 L3 框架吃 diff），不整表重建 DOM。

## 代码风格基线（严格把控——机器拦一半，G3 评审拦另一半）

交付代码是要长期维护的资产，不是一次性脚本；风格以样板（`app-template.html` / `admin-template.py`）为基准。

**JS**：
- 只用 `const`/`let`——**`var` 声明 verify 机器直接拦**（函数作用域是状态混乱之源）；箭头函数、模板字符串、`async/await`；
- 命名有意义：函数动词开头（`loadItems`/`renderList`），禁 `a1`/`tmp2`/拼音缩写；常量全大写下划线；
- 函数 ≤50 行、只做一件事；同一段逻辑出现第 2 次就提成函数；
- 单文件按 数据层/逻辑/渲染/事件 四段分节注释；**无死代码、无注释掉的旧代码、无 console.log/debugger 残留**（debugger 机器拦；console 类输出交付前清，**debugger 语句 verify 机器拦**）；
- 事件统一 addEventListener/委托（内联事件机器拦）。

**Python**：PEP 8 风格、f-string、pathlib、函数 snake_case、`if __name__ == "__main__":` 入口、模块分节注释；异常不吞（中文提示"哪里错、跳过了什么、结果在哪" + 非零退出码）。

**HTML/CSS**：语义化标签；样式只取令牌（禁裸值）；类名 kebab-case（`item-list`，不 `itemList`）；一个组件一段 CSS，按页面结构顺序排列。

**G3 代码走查动作**：对照本节 + execution-craft 代码纪律扫全部主文件——var/残留输出/死代码/复制粘贴段/随意命名 = 打回开发改，**不现场代改**（保持"谁产出谁修复"）。

## 多端与部署自主性（"在哪能用、归谁管"两条底线）

- **多端一套码**：用户要"手机上用"，第一选择是**响应式网页**——同一套代码，手机/电脑/同一 WiFi 的设备都能打开。"只能装进某个平台容器里才能用、别的端全打不开"是**形态事故**，选型时就排除；确需平台能力（支付/推送）才评估容器形态，且 03 写清多端替代路径。
- **部署自主性阶梯（能自己掌控的优先）**：本地程序（双击即用，谁也关不掉）> 自托管静态站（GitHub Pages/对象存储，账号在自己手里）> 自己租的服务器 > 第三方托管平台（小程序云开发/SaaS 建站）。落到别人服务器上的方案，**人家一调整政策/停服你就死**——对外商用类项目默认不选；用户坚持才用，且 03 必须写**平台依赖风险与迁出路径**（数据能不能整份导出、离开平台还剩什么、迁出去要多久），交付说明向用户讲清。
- 小程序类诉求的第一版替代：响应式 H5 + 手机浏览器"添加到主屏幕"，先验证需求；小程序能力属迭代升级项（replica-playbook 的降级思路同源）。

## 双击网页（file://）能力边界表

方案 A/B 在浏览器里以 file:// 打开，能力有边界。技术负责人必须在方案里逐条核对 PRD，不要选了方案 A 才发现功能做不了：

| 能力 | file:// 下 |
|---|---|
| localStorage / IndexedDB、音频播放、拖拽、全屏、打印 | ✅ 可用 |
| 页面内提醒（大字提示 + 声音 + 标题闪烁） | ✅ 可用（提醒类需求的默认替代） |
| 系统通知、摄像头/麦克风、地理定位、推送、跨设备同步 | ❌ 不可用（需 https 或服务端）——第一版不做或换形态 |

方案 E（localhost）不受 file:// 限制：服务端能读写文件、集中存数据、局域网互访；但系统通知、摄像头等浏览器能力同样受 https/权限限制，仍按保守清单核对。

## 数据脚本实现要点（方案 C 深化）

- **编码链**：读文件依次试 utf-8 → gbk → utf-16（或 `errors="replace"` + 中文提示"这个文件的编码有点特殊"）；输出统一 utf-8，**给 Excel 用的 csv 必须 utf-8-sig**（否则 Excel 打开中文乱码）。
- **原始文件神圣**：只读输入；输出写新文件或加后缀（`_汇总.csv`）；同名结果已存在 → 提示或自动加序号，**绝不静默覆盖**。
- **原子写**：先写 `.tmp` 再改名替换，中途失败不留半个坏文件。
- **大文件流式**：逐行/分块处理，不一次读进内存；量级特别大时分批跑。
- **中文交互**：进度（"第 2/5 个…"）、结果（"完成！共 128 行，结果在…"）、报错（哪里错了、跳过了什么、结果在哪）全部中文；窗口结尾 `pause` 不闪退。
- **第三方库**：标准库优先（csv/json/re/sqlite3/datetime/pathlib 几乎够用）；确需 pandas/openpyxl/Pillow → 记录名称/版本/许可证，并附"安装依赖.bat"（`pip install xxx` + 中文提示），使用说明写"第一次用前先双击安装"。

## 商用前台要点（方案 B 升级为 B+）

- **结构**：多页 HTML（页面简单直接）或单页 hash 路由（交互多时）；**零构建**——框架与组件库一律走本地 UMD 引用（按「组件与框架引入阶梯」定级，交互密集的站升 L3 是正常选择而非例外），引构建链（Vite/webpack）才需要写明不可替代理由。公共头尾一处定义——页数 > 5 用几行 JS 注入公共导航，避免逐页手改失同步。
- **设计令牌**：02 的色板/字阶/间距/圆角/阴影固化成 `:root` CSS 变量，全站只引用变量不写裸值；这是"商用级观感稳定"的技术落点。
- **商用清单**（逐项落实）：每页 `<title>` 与 `<meta description>` 各不相同、favicon（内联 SVG data URI）、404 页、加载与空状态、图片懒加载（`loading="lazy"`）+ 宽高属性防跳动 + 压缩、`tel:` 拨号链接、打印样式（如需要）。
- **性能预算**：单页 HTML+CSS+JS < 1MB；首屏图片 < 500KB；本地打开天然快，不为性能引框架。
- **内容先行**：文字与图片素材阶段 1 就跟用户要（PRD 素材清单），素材不齐不进入收尾；版权自查（用户素材/自绘/宽松许可）记录进 03-技术方案。
- **以后放网上**：静态文件夹可直接托管到任意静态空间（GitHub Pages、各家对象存储）；第一版本地验收，发布属正常迭代，全程带用户操作账号注册。

## 性能预算

**商用级数值底线**（SKILL 质量硬闸五柱之①，写进 AC 并实测验收）：启动到可交互 ≤2 秒；任何操作 100ms 内有视觉反馈；连续操作 10 次不掉帧不卡死；admin 万条级列表分页查询 ≤200ms、搜索走索引；数据脚本大文件流式处理且有进度可见。

列表超 1000 条 → 分页或虚拟滚动；数据超 5MB → 换 IndexedDB；单文件超 1MB 考虑拆分。本地文件打开天然快，**不要为"性能"引入框架**——但也不要为"少引一个文件"在 L2/L3 阈值上硬手搓复杂状态，那是逻辑混乱之源，按引入阶梯办（框架本地引用百 KB 级，本地打开无感知）。**重计算/媒体复刻项目另加硬指标**（预览帧率/拖动跟手延迟/导出耗时，从标杆拆解来，验收照此判；降级走"粗预览+精导出"，见 `replica-playbook.md`）。
