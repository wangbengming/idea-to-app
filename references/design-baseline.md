# 设计基线手册（防"AI 味"基准线）

本手册是**设计师岗位的硬约束**（PMO 走查、逐块查验、G3 复核时同样照此审计）。方法论参考 [ibelick/ui-skills](https://github.com/ibelick/ui-skills) 的 baseline 思路，翻译为本技能的**零框架语境**（原生 HTML/CSS/Python，无 Tailwind/React）。

立场：审美判断可以主观，**基线约束必须可执行、可审计**。每条规则分三级：**【禁】**无明确要求不得做；**【必】**必须做；**【宜】**默认做，偏离要在 02 写明理由。

**用法**：设计师动笔前通读一遍，把各维取值落进 02 的「基线自查」节；开发照 02 实现；走查时发现问题按"违例原文 → 为什么 → 怎么改"三段报给开发。某条规则确实需要违反，必须在 02「基线自查」节写明例外与理由——无说明的违例一律算缺陷。

---

## 一、克制（反 AI 味，最高优先级）

AI 生成的界面一眼假，八成坏在这里。逐条【禁】：

- 无明确要求，**不用渐变**——尤其紫色系与多彩渐变横幅。想要"高级感"靠留白、字阶和一套克制的色板，不靠渐变。
- **发光（glow）、霓虹、玻璃拟态大面积磨砂不做主视觉**。阴影用全站统一的一套参数（见 02 视觉节）。
- **一屏只有一个强调色**。强调色滥用的界面没有重点。
- 先用 02 已定的令牌取值，**不引入令牌之外的新颜色/新字号/新间距**。
- 不堆图标、不堆卡片、不堆标签徽章——每个元素都得回答"删掉它用户会损失什么"。

## 二、动效

- 【禁】无明确要求不加**装饰性动画**（飞入、漂浮、循环背景）。交互反馈不算装饰，必须有。
- 【禁】只动合成器属性 `transform` / `opacity`；**不动画布局属性** `width/height/top/left/margin/padding`（会引发重排卡顿）；`color/background` 仅限小范围（文字、图标）。
- 【必】入场用 `ease-out`，时长 150~250ms；交互反馈（按压/悬停）**≤200ms**。
- 【必】尊重 `prefers-reduced-motion`：媒体查询里关掉非必要动画（一行 CSS 的事）：
  ```css
  @media (prefers-reduced-motion: reduce) {
    * { animation: none !important; transition: none !important; }
  }
  ```
- 【宜】循环动画在不可见时暂停；不发明自定义缓动曲线；大图与全屏表面不做动画。

## 三、排版

- 【必】标题用 `text-wrap: balance`（多行标题不再孤字换行）；正文段落用 `text-wrap: pretty`。
- 【必】数字与金额列用 `font-variant-numeric: tabular-nums`（数字对齐，账目类项目尤其重要）。
- 【宜】密集 UI（长标题、列表）用 `text-overflow: ellipsis` 或 `-webkit-line-clamp` 截断，不撑破布局。
- 【禁】默认不调 `letter-spacing`（中文尤其别动）；字号阶梯 ≤3 级（既有规则）。

## 四、布局

- 【必】`z-index` 用固定阶梯（如 10/20/30/40，写进 02），**禁随手 `z-index: 9999`**。
- 【宜】正方形用同一宽高值；移动端满屏高度用 `100dvh` 而非 `100vh`（手机地址栏会吃掉 100vh 的底部）。
- 【必】移动端固定底栏处理安全区：`padding-bottom: env(safe-area-inset-bottom)`。
- 响应式按 02 的断点表逐页落实（front 类既有规则）。

## 五、交互

- 【必】破坏性操作（删除/清空/覆盖）二次确认，确认文案**写清后果**："删除 3 条记录，不可恢复"。
- 【必】加载用**结构骨架**（画一个内容形状的灰色占位），不用孤零零的转圈。
- 【必】错误提示出现在**动作发生的位置**（输入框下面，不是页面角落弹个窗）。
- 【禁】输入框**禁止拦截粘贴**（密码框也不许）。
- 【必】空状态必须有温度且有**一个明确的下一步**："还没录入数据，点右上角『新增』开始"——冷冰冰的"暂无数据"不合格。
- 【必】每个可点元素 100ms 内有视觉响应（既有规则）。

## 六、可访问性（按优先级修）

| 优先级 | 类别 | 硬要求 |
|---|---|---|
| 1 | 可访问名称 | 图标按钮必须有 `aria-label`；每个输入框有 `<label>`；链接用有意义文字（禁"点这里"）；装饰图标 `aria-hidden` |
| 2 | 键盘可达 | 全部交互元素 Tab 可达；别拿 div/span 当按钮 |
| 3 | 焦点与弹层 | 弹窗焦点圈定、Esc 可关、关闭后焦点归位 |
| 4 | 语义 | 用对标签：button/nav/main/table，而不是 div 一把梭 |
| 5 | 表单与错误 | 错误写明"哪里错、怎么改"，与输入框关联（aria-describedby） |
| 6 | 对比度与状态 | 正文对比度 ≥ 4.5:1（既有）；状态不只靠颜色区分（加文字/图标） |
| 7 | 触摸目标 | ≥ 44×44px（既有） |

## 七、性能

- 【禁】大面积 `blur()` / `backdrop-filter` 做动画；【禁】静止元素挂 `will-change`。
- 本地文件打开天然快，不为性能引框架（既有规则）。

## 八、元数据（front 类为必做，其余类型宜做）

- 每页 `<title>` 唯一且格式统一；description 为纯文本、各页不同。
- favicon 用内联 SVG data URI；social 分享卡（og:title/og:description/og:image）在"发布到网上"前补齐。
- 元数据确定性：不出现随机值、不重复标签。

## AI 味速查表（走查时 30 秒扫一遍）

| 长什么样 | 为什么是病 | 怎么改 |
|---|---|---|
| 紫色/多彩渐变横幅、发光按钮 | AI 模板的招牌，廉价感 | 纯色 + 令牌色板，一屏一个强调色 |
| `z-index: 9999` 满天飞 | 层级失控，弹窗压不住 | 固定阶梯 10~40 |
| 什么都在动、入场全飞入 | 廉价动效感 + 性能差 | 只留 ≤200ms 反馈，动 transform/opacity |
| 加载 = 一个转圈 | 用户不知道在加载什么 | 结构骨架占位 |
| 空状态一句"暂无数据" | 用户不知道下一步干嘛 | 一句温度话 + 一个明确按钮 |
| 圆角三处三个样、阴影两套 | 没有系统感 | 全站统一参数（02 视觉节） |
| 表格数字没对齐 | 不专业 | tabular-nums |
| 手机上底部按钮被地址栏吃掉 | 100vh 的锅 | 100dvh + safe-area |
| 图标按钮无 aria-label | 读屏器读不出是什么 | 补 label |
| 输入框不让粘贴 | 逆用户而行 | 删掉拦截代码 |

## 三证明审计法（走查/查验时的报缺陷纪律）

审计的对象是**交付物对照 02 自己声明的系统**，不是审计师的个人审美。发现一个问题必须三证齐全才能报：

1. **合同**：02 里真写了这条规则/取值（或本基线手册的【必】【禁】条目）——"我觉得应该"不算；
2. **运行时**：页面确实触达了该问题（引用具体页面/交互路径）；
3. **修正**：能给出唯一、具体的改法（"把这三个按钮统一为 02 的 --radius 值"）——给不出唯一改法说明自己没想清，不报。

三证不齐**宁可不报**。通过的缺陷填入查验记录：

```
| 问题 | 证据（02 条款 + 页面位置） | 修改建议 | 置信度 |
```

最多 3 条，按用户影响排序，修复后复核。全部走查通过才算该块"设计走查过"。

**向用户翻译**时只说人话："这一块按钮有三种样式，我统一成一种""手机上底部的按钮会被浏览器的地址栏挡住，我修了"。
