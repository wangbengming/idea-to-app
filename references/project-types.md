# 项目类型手册：单机工具 / 数据脚本 / 管理后台 / 商用前台

本手册是**项目经理（PMO）在阶段 0 的归类依据**，也是各岗位做类型增量时的速查。类型在 `init --type` 时写入状态文件，决定：模板集（`assets/templates/<类型>/`）、派工单增量、门禁章节要求、verify 检查分支与交付形态。

**铁律：类型只改"做什么"的侧重，不改五阶段、四道门与沟通铁律。**对用户永远说人话——数据脚本是"帮你批量整理文件的小程序"，后台是"你们几个人分工用的小系统"，前台是"给客户看的官网"。

## 归类判定（阶段 0 听懂需求后立即做，不问用户）

| 类型 | 用户嘴里的信号 | 关键追问（都是使用问题） | 默认规模 | 默认形态 |
|---|---|---|---|---|
| tool 单机工具（默认） | 记个账、列个单、倒计时、换算、查个东西 | 自己一个人用吗？ | 小 / 中 | A 单文件网页 |
| data 数据脚本 | 批量处理文件、整理一堆资料、生成报表、定时跑、文件太多改不过来 | 文件从哪来？处理完给谁看？多久跑一次？ | 中 | C Python 脚本 + 双击启动 |
| admin 管理后台 | 录入/管理一批资料（进销存、台账、客户资料）、几个人分着用、要登录 | 哪几个人用？分工是什么？谁能看、谁能改？ | large / xl | E 本地服务 + 数据库 |
| front 商用前台 | 给客户看的官网、门店页、活动页；要好看、要专业 | 访客看完做什么（打电话/到店/下单）？内容（文字图片）谁来给？ | 中 / large | B+ 多页商用级 |

**混合型的归一**：按项目的主要价值归类，次要侧并入。
- 后台 + 对外展示页 → `admin` 为主，展示页做进后台的公开路由；
- 网站要登录才有内容 → 先跟用户确认到底是不是"几个人管资料"：是则 `admin`，只是"我自己的资料"则 `tool`；
- 定时抓数据再展示 → 数据获取归 `data` 思路，展示归所属类型，第一版拆清先后。

拿不准就 `tool`（步骤最少）。归类错了代价也不大：`init` 后在《05-发布记录》写明改型，重跑 `init --type` 即可。

## 积木块切分与安全/部署速配

《00-项目规划书》的拆块心法：**一块 = 用户能看懂、能亲手查验的一个完整体验**（不是技术分层），第 1 块永远是最小可用骨架。按类型速配：

| 类型 | 积木块切法（示例） | 安全部重点（07 清单） | 竣工后的部署建议方向 |
|---|---|---|---|
| tool | 1~2 块（小项目免规划书） | 有表单/敏感数据才派 sec | 换电脑用、分享给他人 |
| data | 读入 → 清洗转换 → 汇总输出 → 异常兜底 | 输入文件攻击面（路径穿越/超大文件/伪装数据） | 定时自动运行、结果送达 |
| admin | 登录骨架 → 主实体增删改查 → 第二实体/权限 → 备份与账号 | 密码与会话、路由级权限、备份保管、内置账号改密 | 自动备份、同一 WiFi 开放（公网默认劝退） |
| front | 首页（含核心动作） → 内容页 → 详情/联系 → 404 与打磨 | 表单去向、素材版权、本地文件完整性 | 静态托管上线（免费）、域名（花钱） |

安全派工节奏：只派一次，在开发完成后、测试之前；"严重"级问题有一票缓发权。部署动作只在竣工（G4 + 全部块查验）后开始，选项与话术见 `references/deploy-recipes.md`。

## 对编制的影响

类型与规模独立；规模判定仍按 SKILL.md 的编制表。类型带来的默认调整：

- `admin` **至少 large**（独立技术负责人出权限与数据方案）；页面/实体特别多时用 **xl**：开发拆**前端 + 后端**两岗（`dispatch fe` / `dispatch be`）。
- `front` 气质权重高，设计师派工时 brief 里附上用户指过的参考网站与行业。
- `data` 通常 medium 足够；输入格式特别乱、来源多时也只加 TL 派工，不拆前后端。
- **叠加信号调编制**：对外/售卖/给客户（商用级信号）→ 下限 medium（对外后台/商用前台建议 large）；**对标复刻命中 replica-playbook → medium 起步**；重计算/媒体类（视频音频处理）→ 建议 large（技术对标与形态适配工作量实打实）。

## data · 数据脚本

**画像**：用户有一堆重复的手工操作（改文件名、汇总表格、转格式），电脑上有 Python 或愿意装。没有"界面审美"问题，有"出错恐慌"问题——他们最怕"把我原文件搞坏了"。

### 各阶段差异

| 阶段 | 增量 |
|---|---|
| 0 复述 | 复述"输入什么 → 变成什么"，例："你把文件放进文件夹，双击一下，它把 300 张照片按拍摄日期改名" |
| 1 需求 | PM 必须拿到：**输入与输出契约**（格式/编码/列名/放哪）+ **数据样例**各一份。用户给不出样例就请他现在导一份——没有样例不开发 |
| 2 设计 | 设计岗不做页面，出**处理流程 + 异常提示文案 + 输出样式**（模板已换） |
| 3 开发 | 交付物 = `.py` + `启动.bat`（bat 三件套：chcp 65001 / cd /d %~dp0 / pause）。PMO 走查 = **真实运行**，不点浏览器 |
| 4 测试 | QA 真实跑样例 + **异常输入**（空文件/坏编码/缺列）；G4 机器校验「异常输入测试」章节 |

### AC 写法

必须"可运行可判对错"，并写进运行方式：`把 sample.xlsx 放进应用文件夹，双击 启动.bat，10 秒内生成 汇总.csv，共 128 行`。

### 红线（写入 PRD 不做清单与技术方案）

1. **原始输入文件只读**，结果一律写新文件——这是数据脚本类的第一安全底线，交付说明里也要红字写。
2. 编码兜底：中文文件 utf-8/gbk 都要能读；给 Excel 看的 csv 用 utf-8-sig。
3. 报错中文且给出路（"第 3 个文件缺'金额'列，已跳过，其他正常"），窗口不闪退（pause）。
4. 大文件流式处理，不一次读进内存。

### 常见坑

用户说的"Excel"可能是 .xlsx 也可能是 .csv；"每个月"意味着要能重复跑（同名结果不静默覆盖）；用户的文件编码永远出乎意料。

## admin · 管理后台

**画像**：小团队（几个人到几十个人）分角色管一批资料。用户第一次需要"账号"概念——解释成"每人一个自己的用户名密码，系统记得是谁干的"。

### 各阶段差异

| 阶段 | 增量 |
|---|---|
| 0 复述 | 复述"谁 + 管什么 + 分什么工"："你和两个店员都能记销售，只有你能改价格、看全部记录" |
| 1 需求 | PM 产出**实体与角色**节：实体字段表 + 角色清单 + **权限矩阵逐格跟用户确认**（谁能看/改什么）。这是后台的命根子，一格都不许想当然 |
| 2 设计 | 后台三件套：导航框架 + 列表页（搜索/筛选/分页/批量）+ 表单页；加**权限呈现**节（不同角色界面差异）。风格族从 design-craft.md 族谱 admin 段选（数据密度/分层卡片/企业规范），间距取密集档、动效取克制档；行业反模式认领见手册第七节 |
| 3 开发 | 形态 E：以 `assets/admin-template.py` 为骨架（登录/会话/权限/备份内置）。TL 的权限校验点清单逐路由落实；实体页 ≥3 或交互密集时按引入阶梯升 L4 本地组件库（服务端结构不动）；xl 规模拆 fe/be 两岗（fe 管界面呈现、be 管服务端与校验，同一份 06 各自追加） |
| 4 测试 | QA 做接口级测试 + **角色权限矩阵逐格验证**（未授权账号直接访问 URL 必须服务端拒绝）；G4 机器校验「角色权限测试」章节。PMO 走查 = 每个角色真实登录走一遍主流程 |

### AC 写法

按角色写，权限类必须含"直接输网址也进不去"：`店员账号登录后导航不出现"价格设置"，直接访问该页提示"无权限"（服务端拒绝）`。

### 红线

1. 密码 pbkdf2 加盐存储，禁止明文（verify 强制检查）。
2. 每个功能在**服务端**校验角色，界面藏菜单只是呈现不是安全。
3. 内置管理员首次登录必须改密；登录失败限速。
4. "备份数据"按钮必备（复制 data.db 到 backups/）；交付说明教用户"复制那个数据文件就是备份"。
5. 形态 E 只限本机/可信内网（无 HTTPS/CSRF）；用户要公网访问 → 列入"以后再说"并说明代价，不悄悄答应。

### 对用户解释形态的话术要点

"双击『启动』，系统会在浏览器里打开；用完把那个黑窗口关掉，系统就关了。资料都存在你们自己电脑里的一个数据文件里，复制一份就是备份。想在同一 WiFi 的手机上用也行，我给你打开那个开关。"——**不说"服务器""端口""数据库"**，最多说"数据文件"。

### 常见坑

用户说"几个人用"可能其实是"几个人轮着在一台电脑用"（那是 tool，不用账号）；权限矩阵里"老板全权 + 店员只能录"是最常见的最小集，别加戏；忘密码的出路（找管理员重置）要写进使用说明。

## front · 商用前台

**画像**：给客户/访客看的门面。质量标尺从"能用"升级为"敢拿去见客户"：气质、手机体验、每页标题、图片加载。最大的风险不是技术，是**内容**——文字图片要甲方给。

### 各阶段差异

| 阶段 | 增量 |
|---|---|
| 0 复述 | 复述"给谁看、看完做什么"："让顾客在手机上 10 秒看懂你们卖什么，然后愿意打电话" |
| 1 需求 | PM 产出**页面结构**节：页面树 + 每页职责 + **素材清单**（要用户提供什么文字图片、Logo 有无、什么时候给）。内容没着落就是最大的进度风险 |
| 2 设计 | 趋势侦察权重最高的一类；按 design-craft.md 五步法走：**风格定位**（族谱 front 段 7 族按行业选）→ **设计令牌**（五套令牌：色彩 16 语义位/字体/宽松档间距/深度阶梯/动效档）+ **响应式**（断点与逐页调整）；每页注明所用区块模式（手册第四节区块库）。设计师要主动给用户看 1~2 张风格样品（probe 流程照用） |
| 3 开发 | 多页静态文件夹（零构建；组件与框架走本地 UMD 引用，按 tech-recipes 引入阶梯定级，交互密集可升 L3）；公共导航一处定义（页多则 js 注入）；每页 title/description/favicon；404、加载与空状态逐页落实 |
| 4 测试 | QA 逐页检查 title/空态/跨页返回；响应式列进走查清单，**PMO 必须用手机宽度真实走查**（browser-use 设窄视口） |

### AC 写法

含设备维度：`手机宽度（375px）打开首页：第一屏完整展示店名、主推产品与"打电话"按钮，无横向滚动`。

### 红线

1. 样式只从 02 的设计令牌取值，页面里不写裸值。
2. 每页有 title 与 viewport；图片本地、压缩、懒加载。
3. 素材版权：只用用户素材/自绘 SVG/宽松许可证，来源记进 03-技术方案。
4. 核心动作（打电话/加微信/到店导航）在每一页一屏内可达。

### "以后放网上"的迭代路径

第一版本地验收后，用户几乎必然问"能不能放到网上让客人看"。标准应答："可以，这种网站放到网上很简单，等你对现在的样子满意了，跟我说一声，我带你把它发上去（有免费的托管地方）。"技术上：静态文件夹可直接托管到 GitHub Pages / 对象存储等，属正常迭代——但发布动作涉及账号注册，届时全程带着用户操作，并按 phrasebook 的话术解释每一步。

### 常见坑

用户给的"参考网站"可能是竞品（只取手法不抄结构，设计师版权红线）；手机优先但用户只在电脑上看你演示——交付前务必自己先用手机宽度过一遍；内容素材拖到最后一刻才要是最常见的延期原因，阶段 1 就开口。

## 新类型扩展指引（给未来的自己）

新增类型 = 四步，全部围绕状态文件里的 `type`：

1. `assets/templates/<type>/` 放差异模板（01~04，文件名不变，init 自动优先取用）；
2. `pm.py` 的 `DISPATCH[*]["type_must"]` 加派工增量（含 sec 岗），`G1_HEADERS / G2_HEADERS / G4_EXTRA_HEADERS` 加门禁章节，`run_verify` 加检查分支，`G4` 的安全清单触发条件按需调整；
3. `references/tech-recipes.md` 补交付形态与实现要点，`references/deploy-recipes.md` 补部署选项；
4. 本手册补"识别信号 / 阶段差异 / 红线 / 坑 / 积木块切分"，SKILL.md 画像表加一行。

顺序建议：先写模板（定义"好文档长什么样"），再补门禁（机器怎么验），最后写手册（人怎么判）。
